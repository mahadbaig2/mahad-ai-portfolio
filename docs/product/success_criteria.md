# Measurable Product Success Criteria

This document defines the quantitative and qualitative success criteria for Mahad's AI Portfolio and the "Talk to Mahad" system.

---

## 1. Usability Without AI (Base Site Performance)

- **Requirement**: The core web application (portfolio, case studies, blog, experience, contact details) must remain 100% usable and informative even if all AI/backend services are completely offline.
- **Criteria**:
  - 100% of static portfolio routes (`/`, `/work`, `/work/[slug]`, `/blog`, `/about`, `/contact`) render cleanly without relying on FastAPI, Qdrant, Neon, or Groq.
  - Zero layout shift (CLS < 0.1) or broken page states when AI services return errors or timed out requests.
  - Full keyboard navigation and WCAG AA contrast compliance across all core pages.

---

## 2. Grounded Citations & Factuality

- **Requirement**: The "Talk to Mahad" assistant must only provide factual answers grounded in verified source content managed in Sanity CMS.
- **Criteria**:
  - **100% Citation Rate for Factual Claims**: Every factual claim generated by the assistant (excluding deterministic navigation/greeting responses) must link to at least one valid source chunk ID returned by the current retrieval run.
  - **Zero Hallucinated Facts**: The assistant must clarify or refuse unsupported questions rather than inventing details from base LLM memory.
  - **Strict Citation Validation**: Claim-to-source verification logic in the graph blocks any response token payload that references unretrieved source IDs.

---

## 3. Cost Control & Bounded Resource Usage

- **Requirement**: The production system must operate strictly within free-tier resource boundaries with guaranteed zero unexpected billing.
- **Criteria**:
  - **Zero Billable Services**: 100% of infrastructure runs on explicit free tiers (Cloudflare Free, Sanity Free, Neon Free, Qdrant Free Cluster, Groq Free Tier, Hugging Face CPU Basic Spaces).
  - **Hard Usage Protection**: LangSmith tracing includes monthly hard-disable thresholds set below free-tier caps; model serving runs in-process on CPU to avoid paid GPU hosting.
  - **Resource Auditing**: Monthly free-tier audits logged in `docs/runbooks/free-tier-audit.md`.

---

## 4. Mobile & Multi-Device Support

- **Requirement**: The entire user experience—including chat, voice input, and the execution inspector—must be fluid, readable, and responsive across all device sizes.
- **Criteria**:
  - **Responsive Breakpoints**: Flawless visual display across screen widths from 320px (mobile) to 2560px (desktop).
  - **Mobile Voice & Touch**: Push-to-talk microphone controls optimized for mobile touch targets (minimum 44x44px target size).
  - **Performance**: Mobile Lighthouse score >= 90 for performance, accessibility, and best practices.

---

## 5. Graceful Degradation & Resilience

- **Requirement**: System failures in downstream AI, vector, database, or observability providers must produce controlled user-facing states without application crashes.
- **Criteria**:
  - **LangSmith Outage Resilience**: If LangSmith API calls fail or timeout, user chat requests complete normally with zero error impact.
  - **Vector DB / API Degradation**: If Qdrant or Groq fails or rate limits, the UI displays a clear, human-readable status message and directs users to static portfolio content.
  - **Speech Synthesis Fallback**: If OpenVoice cloned voice generation is unavailable or times out, the system automatically falls back to browser `window.speechSynthesis` or displays text-only output.
